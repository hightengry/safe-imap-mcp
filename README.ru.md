# safe-imap-mcp

**Даёт Claude (или любому ИИ-ассистенту с поддержкой MCP) читать и отправлять вашу почту по IMAP/SMTP, но не даёт ничего удалять.**

[English version](README.md)

Большинство почтовых интеграций для ИИ-ассистентов работают только с Gmail и Microsoft 365 или дают модели полный контроль над ящиком. `safe-imap-mcp` это небольшой локальный [MCP](https://modelcontextprotocol.io)-сервер для частого случая посередине: рабочие ящики у обычного хостинга (cPanel, Plesk, свой почтовый сервер), где ассистент должен искать, читать, готовить черновики и отправлять письма, но один неверный вызов не должен стереть ваши «Входящие».

- Работает с любым IMAP/SMTP-сервером и с несколькими ящиками одновременно.
- Запускается на вашем компьютере. Пароли хранятся там и передаются только вашему почтовому серверу, всегда в зашифрованном виде.
- **Инструментов для удаления, перемещения и очистки писем нет.** Автоматический тест проверяет, что таких вызовов нет в коде.
- Чтение письма не отмечает его прочитанным.
- Прикладывать можно только файлы из разрешённых вами папок. Файлы с ключами и паролями не прикладываются никогда.
- По желанию можно задать «папки с подтверждением»: файл оттуда приложится только после того, как вы нажмёте «Да» в окне на своём компьютере. Ассистент ответить в этом окне не может.

## Что может ассистент

| Инструмент | Что делает | Меняет что-то? |
|---|---|---|
| `list_accounts` | Список подключённых ящиков | Нет |
| `list_folders` | Папки ящика | Нет |
| `search_emails` | Поиск по отправителю, получателю, теме, тексту, датам, непрочитанным | Нет |
| `read_email` | Читает письмо целиком, показывает вложения | Нет (не отмечает прочитанным) |
| `list_attachment_folders` | Показывает разрешённые папки для вложений и куда сохраняются вложения | Нет |
| `mark_as_read` | Ставит или снимает отметку «прочитано» | Только эту отметку |
| `save_attachments` | Сохраняет вложения письма в `Загрузки/mail-attachments` | Создаёт там новые файлы, не перезаписывает |
| `save_draft` | Сохраняет письмо в «Черновики» | Добавляет черновик |
| `send_email` | Отправляет письмо, в том числе ответом в той же переписке и с вложениями; кладёт копию в «Отправленные» | Отправляет письмо |

Инструментов для удаления, перемещения, архивации и очистки нет специально. Создавать и удалять ящики тоже нельзя.

## Что нужно

- [Node.js](https://nodejs.org) версии 20 или новее
- MCP-клиент: Claude Desktop, Claude Code или другой клиент с поддержкой локальных (stdio) MCP-серверов
- Доступ к ящику по IMAP и SMTP с паролем или паролем приложения

## Установка

### 1. Скачать

```bash
git clone https://github.com/hightengry/safe-imap-mcp.git
cd safe-imap-mcp
npm ci
```

Или скачайте ZIP с GitHub, распакуйте и выполните `npm ci` в папке. Команда `npm ci` ставит ровно те версии библиотек, которые записаны в `package-lock.json`.

По возможности держите папку программы вне Рабочего стола, Документов и Загрузок (например, `C:\Tools\safe-imap-mcp` или `~/tools/safe-imap-mcp`). Коннектор в любом случае не прикладывает файлы из своей папки, но это хорошая привычка.

### 2. Настроить ящики

```bash
cp accounts.example.json accounts.json      # Windows: copy accounts.example.json accounts.json
```

Отредактируйте `accounts.json`:

```json
{
  "defaults": {
    "imapHost": "mail.example.com",
    "imapPort": 993,
    "smtpHost": "mail.example.com",
    "smtpPort": 465
  },
  "accounts": [
    { "email": "you@example.com", "fromName": "Ваше Имя", "password": "ваш-пароль" },
    { "email": "info@example.com", "fromName": "Компания", "passwordEnv": "MAIL_PASSWORD_INFO" }
  ]
}
```

Имена серверов и порты обычно есть в панели хостинга в разделе вроде «Настройка почтового клиента» или «Ручная настройка».

Файл `accounts.json` внесён в `.gitignore` и не попадёт в репозиторий.

### 3. Проверить связь

```bash
npm run check
```

Команда входит в IMAP и SMTP каждого ящика и пишет `ok` или ошибку. Ничего не отправляет и ничего не меняет.

### 4. Подключить к ассистенту

**Claude Desktop.** Откройте *Settings → Developer → Edit Config* и добавьте сервер в `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "email": {
      "command": "node",
      "args": ["C:\\path\\to\\safe-imap-mcp\\index.js"]
    }
  }
}
```

На macOS и Linux путь обычный, например `"/Users/you/safe-imap-mcp/index.js"`. Если раздел `mcpServers` в файле уже есть, добавьте в него только блок `"email": {...}`. Полностью закройте Claude Desktop и откройте снова.

Если Claude пишет, что не находит `node`, укажите полный путь, например `"C:\\Program Files\\nodejs\\node.exe"` или результат команды `which node`.

**Claude Code.**

```bash
claude mcp add email -- node /path/to/safe-imap-mcp/index.js
```

**Другие клиенты:** запускайте `node index.js` как stdio MCP-сервер.

### 5. Проверить

> Покажи 5 последних писем в ящике you@example.com.

## Настройки

| Ключ | Где | По умолчанию | Значение |
|---|---|---|---|
| `email` | ящик | обязательно | Адрес ящика, по нему выбирается ящик |
| `fromName` | ящик | нет | Имя отправителя в поле «От» |
| `password` | ящик | нет | Пароль или пароль приложения |
| `passwordEnv` | ящик | нет | Имя переменной окружения с паролем (вместо `password`) |
| `username` | ящик / defaults | `email` | Логин, если отличается от адреса |
| `imapHost`, `smtpHost` | ящик / defaults | обязательно | Имена серверов |
| `imapPort` | ящик / defaults | `993` | Порт IMAP |
| `smtpPort` | ящик / defaults | `465` | Порт SMTP (`587` использует STARTTLS) |
| `imapSecure`, `smtpSecure` | ящик / defaults | по порту | Принудительно включить или выключить TLS |
| `attachmentFolders` | верхний уровень | Рабочий стол, Документы, Загрузки (и варианты OneDrive) | Откуда можно прикладывать файлы свободно. `[]` значит ниоткуда |
| `approvalFolders` | верхний уровень | нет | Откуда можно прикладывать файлы только после нажатия **«Да»** в окне на вашем компьютере (Windows, macOS; в Linux нужен `zenity`) |
| `saveFolder` | верхний уровень | `Загрузки/mail-attachments` | Единственная папка, куда сохраняются полученные вложения |
| `limits.maxRecipients` | верхний уровень | `20` | Максимум адресатов (to + cc + bcc) в письме |
| `limits.maxAttachments` | верхний уровень | `10` | Максимум вложений в письме |
| `limits.maxAttachmentMB` | верхний уровень | `20` | Максимальный общий размер вложений |
| `limits.maxSendsPerHour` | верхний уровень | `20` | Максимум отправленных писем в час (считается, пока сервер запущен) |

Пример строгой настройки: свободно прикладывать только из одной папки, из проектов только с подтверждением:

```json
{
  "attachmentFolders": ["C:\\Users\\you\\Documents\\Outgoing"],
  "approvalFolders": ["D:\\Work"],
  "defaults": { "...": "..." },
  "accounts": [ "..." ]
}
```

Файл настроек перечитывается при каждом вызове, поэтому пароли и лимиты можно менять без перезапуска. Чтобы хранить настройки в другом месте, задайте переменную `MAIL_ACCOUNTS_FILE=/путь/к/accounts.json` (в Claude Desktop это делается блоком `"env"` рядом с `"args"`).

## Как устроена безопасность

Задача конструкции: запутавшийся, ошибившийся или обманутый ассистент не может уничтожить почту и не может ничего отправить без вашего одобрения. Ниже как это устроено и где пределы.

1. **Нет разрушительных операций.** Нет ни инструментов, ни кода, который удаляет, перемещает, копирует, очищает или переименовывает письма и папки, и никогда не ставится IMAP-отметка `\Deleted`. `npm test` проверяет исходный код на такие вызовы: это ловит ошибки, но не является формальным доказательством. Все инструменты помечены `destructiveHint: false`.
2. **Чтение без последствий.** Для поиска и чтения ящик открывается только на чтение.
3. **Отправка с одобрения человека.** Описание `send_email` требует от ассистента показать отправителя, адресатов, тему, полный текст и пути к вложениям и дождаться вашего явного согласия. В Claude Desktop на запрос разрешения для `send_email` отвечайте **Allow once (Разрешить один раз)**, а не «Всегда», тогда каждую отправку нужно подтверждать кнопкой.
4. **Защита от подсказок в письмах.** Входящие письма считаются недоверенными. Инструменты велят ассистенту воспринимать текст писем как данные и не прикладывать файлы, не добавлять адресатов, не отмечать письма прочитанными и не сохранять вложения только потому, что об этом просит письмо. Это зависит от того, слушается ли ассистент, поэтому пункты 3, 5 и 6 от этого не зависят.
5. **Песочница для вложений.** Файлы можно брать только из `attachmentFolders` и `approvalFolders`. Путь сначала приводится к настоящему файлу (ссылки, короткие имена Windows). Сетевые пути (`\\server\share`), альтернативные потоки данных и имена с точкой или пробелом в конце отклоняются ещё до обращения к диску. Папка программы, файл настроек и журнал отправок закрыты по идентичности файла, поэтому переименованный путь или жёсткая ссылка не помогут. Файлы, где обычно хранятся секреты, не прикладываются никогда: скрытые файлы и папки (`.env`, `.ssh`, `.git` и подобные), ключи SSH, `.pem/.key/.pfx/.p12`, базы паролей (`.kdbx`), архивы почты (`.pst`), `.rdp/.ovpn`, `accounts*.json`, `credentials.*`, `secrets.*`.
6. **Подтверждение на компьютере.** Файлы из `approvalFolders` прикладываются только после нажатия **«Да»** в системном окне. Ассистент не может в нём ответить, а если ответа нет 45 секунд, окно закрывается с ответом «Нет». Окно всегда появляется поверх других окон.
7. **Безопасное сохранение.** Полученные вложения сохраняются только в `saveFolder`, с безопасными именами (без обходов пути, без зарезервированных имён Windows, без подмены расширения через символы письма справа налево) и без перезаписи. В Windows они помечаются как скачанные из интернета, поэтому SmartScreen и защищённый просмотр Office продолжают предупреждать. Коннектор их не открывает.
8. **Шифрование.** На портах без встроенного TLS обязателен STARTTLS, поэтому пароль никогда не передаётся открытым текстом.
9. **Видимые адресаты.** Каждая запись адресата должна содержать ровно один адрес, поэтому кому письмо показано, тому оно и уходит. Скрытая копия (Bcc) не видна получателям, но сохраняется в вашей копии в «Отправленных» и «Черновиках».
10. **Лимиты.** Ограничены число адресатов и вложений в письме и число писем в час.
11. **Журнал.** Каждое отправленное письмо записывается в `sent-log.txt` рядом с файлом настроек: время, отправитель, адресаты, тема, вложения.

### От чего это не защищает

- **Пароли на диске.** `accounts.json` хранит пароли открытым текстом, если не использовать `passwordEnv`. Их может прочитать любой, у кого есть доступ к вашей учётной записи на компьютере. Используйте пароли приложений, если провайдер их поддерживает, и не передавайте файл.
- **Одобрение неудачного письма.** Если вы одобрили письмо, оно уйдёт. Читайте, что одобряете.
- **Функции самого почтового сервиса.** Серверные фильтры, правила пересылки и веб-почта вне зоны действия инструмента.
- **Вводящее в заблуждение содержимое.** Письмо может показывать в HTML-виде другой текст, чем в текстовой части, или прятать текст оформлением. Ассистент читает текстовую часть, если она есть. Не доверяйте пересказу подозрительного письма больше, чем самому письму.
- **Конфиденциальные файлы с обычными именами.** Банковскую выписку или скан документа из разрешённой папки можно приложить, если вы одобрите письмо. Держите `attachmentFolders` как можно уже.
- **Часовой лимит сбрасывается при перезапуске сервера.**

Как сообщить об уязвимости: [SECURITY.md](SECURITY.md).

## Совместимость

- **Почта на хостинге (Plesk, cPanel, DirectAdmin, Dovecot/Postfix):** основной сценарий, вход по паролю.
- **Thunderbird, Outlook и другие почтовые программы:** не нужны и не затрагиваются. Коннектор подключается к тем же ящикам на почтовом сервере напрямую, поэтому почтовой программой можно пользоваться как раньше, плагин не нужен. Письма, которые лежат только в локальных папках программы (не на сервере), коннектору не видны.
- **Gmail / Google Workspace:** работает с `imap.gmail.com` / `smtp.gmail.com` и паролем приложения, если аккаунт или администратор ещё разрешают пароли приложений. Gmail сам сохраняет отправленные письма, поэтому в «Отправленных» может появиться две копии.
- **Microsoft 365 / Outlook.com:** требуют OAuth для IMAP/SMTP, этот инструмент его не поддерживает. Используйте официальный коннектор Microsoft 365 вашего ассистента.
- Письма отправляются обычным текстом, без HTML-оформления.

## Разработка

```bash
npm test        # офлайн-тесты безопасности, почтовый сервер не нужен

```
